# 向量数据库进阶 · 课程大纲

上一章你用 FAISS 学会了向量索引的核心思路。但 FAISS 本质是一个"库"：数据存在内存/文件里，没有服务、没有账号、没有现成的增删改查接口，多个程序想用它还得自己包一层。

真正做项目时，你往往需要一个"数据库"：能把向量和原文、元数据一起持久化保存，重启不丢；能方便地增删改查、按条件过滤；最好还能作为一个服务，让多个应用同时连接。这一章我们就走进几个主流的完整向量数据库——上手最简单的 Chroma、为大规模而生的 Milvus、以及"寄居"在传统数据库里的 PGVector，再回头讲透索引算法和选型方法。

## 学习之前

- 已学完第 07 章（FAISS），理解向量、相似度、ANN 和"速度/内存/准确率"的权衡
- 本章所有数据库都有 CPU 版、本机可跑，不需要显卡；我们仍用小数据练习
- 安装环节可能遇到各种环境问题，别慌，课程会给出常见坑和替代方案

## 课次安排

| 课次 | 主题 | 你会搞懂的事 |
|------|------|--------------|
| 第 01 课 | Chroma：最友好的入门数据库 | 集合、文档、元数据；CRUD 与过滤；持久化到本地；内嵌嵌入函数怎么用 |
| 第 02 课 | Milvus：为大规模而生 | Collection、字段、分区；从建表到检索的完整流程；Lite/Standalone 几种部署形态 |
| 第 03 课 | PGVector：在 PostgreSQL 里做检索 | 为什么关系数据库也要加向量类型；建扩展、建表、混合查询（结构化条件+向量相似） |
| 第 04 课 | 向量索引算法讲透 | IVF、HNSW、PQ 等跨库通用索引原理，以及各数据库实现上的差异（FAISS 怎么调参已在第 7 章练过，这里讲通用道理，不重复） |
| 第 05 课 | 向量数据库选型 | 按数据规模、性能、运维、功能、成本几个维度，建立自己的选型判断 |

> 第 03 课 PGVector 课内自带【SQL 最小速成】小框：CREATE TABLE、SELECT、ILIKE 这几句"生存 SQL"够用即可，不新增章节；完全不想碰 SQL 的话，课里也给了 psycopg 封装的零 SQL 用法。

## 怎么学

1. 每学一个库都亲手完成"建集合→写入→检索→删除"闭环，再看它和 FAISS 的区别
2. 重点体会三件事：**持久化、元数据过滤、服务化**——这是"库"和"数据库"的分水岭
3. 第 04 课的算法是解释所有数据库行为的钥匙，和第 7 章对照着看，会豁然开朗
4. 第 05 课别背对比表，学会"面对一个真实项目需求，该问哪些问题"
