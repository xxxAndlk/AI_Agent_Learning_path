# 第 03 课　PGVector：在 PostgreSQL 里检索向量

前两课都在新装数据库。但很多公司已经在运行 PostgreSQL（老牌开源关系数据库），为向量检索再养一套专用库，运维成本会翻倍。PGVector 的思路是给 PostgreSQL 装一个扩展插件，让现有数据库直接支持存向量、搜向量。

用 PGVector 需要一点 SQL 基础。SQL 是操作关系数据库的标准语言，本课先用五分钟补足够用的部分，后面再给不写 SQL 的封装用法。

## 【SQL 最小速成】五分钟生存包

SQL 就是"向数据库提要求的句子"，逐句看：

```sql
-- 1. 建表：定义有哪些列（embedding vector(4) 就是 PGVector 新增的向量列）
CREATE TABLE dishes (id serial PRIMARY KEY, content text, price numeric, embedding vector(4));

-- 2. 查询：SELECT 列 FROM 表 WHERE 条件
SELECT content, price FROM dishes WHERE price <= 50;

-- 3. 模糊匹配：ILIKE 不区分大小写地"包含某词"
SELECT content FROM dishes WHERE content ILIKE '%红烧%';

-- 4. 向量排序：<=> 算余弦距离，取最近的前 2 条
SELECT content FROM dishes ORDER BY embedding <=> '[0.1,0.2,0.3,0.4]' LIMIT 2;
```

`<=>`、`<->`、`<#>` 三个距离运算符分别对应余弦距离、欧氏距离、内积（取负方便排序），第 2 章讲过的三种"像不像"度量，在 SQL 里就是这三个符号。更实用的是**混合查询**：`WHERE price <= 50 ... ORDER BY embedding <=> ...`，价格过滤和语义排序在同一条 SQL 里完成，这是不少专用向量库要额外设计才能提供的能力。

## 不写 SQL 的用法：psycopg 封装

不想写 SQL 也可以。Python 的 PostgreSQL 驱动 **psycopg**（2026 年主流是 psycopg 3，旧代码里的 psycopg2 会认即可）配合 pgvector 官方适配包，能把 SQL 全部藏进函数里：建表、插入、搜索都调用封装好的方法，向量直接传 Python 列表，参数用 `%s` 占位防注入，一行 SQL 不用写。本课演示代码就是这样实现的；上面的速成包需要"看得懂"，不必天天手写。

```mermaid
flowchart LR

    B --> C1[content 文本列]
    B --> C2[price 数值列]
    B --> C3[embedding 向量列]
    A -- search 查询向量 价格上限 --> B
    B --> D[WHERE 过滤 + 向量距离排序 一次完成]
```

## 小结

- PGVector = PostgreSQL 的向量扩展：老数据库，新能力，数据不搬家。
- SQL 生存四句：CREATE TABLE / SELECT / WHERE / ORDER BY ... LIMIT；ILIKE 管模糊匹配。
- `<=>`、`<->`、`<#>` 对应余弦、欧氏、内积三种距离。
- psycopg 封装可零 SQL 开发，但看得懂 SQL 才不慌。
