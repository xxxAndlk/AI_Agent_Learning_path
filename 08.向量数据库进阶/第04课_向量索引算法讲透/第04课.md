# 第 04 课　向量索引算法讲透

第 7 章第 02 课，我们在 FAISS 里第一次见到 IVF、HNSW、PQ，也亲手调过 nprobe、efSearch 这些参数。本课不重复调参，而是换一个视角：这三种思路不属于 FAISS 一家，它们是整个向量检索领域的通用方法。Chroma、Milvus、PGVector 文档里的索引类型，基本都是这三类的组合或变体。

## 三种思路，各省一样东西

- **IVF：省计算**。写入时按聚类分堆，查询只搜最近的几堆，扫描范围从全库缩小到几个分区。
- **HNSW：省路径**。建图时按层级组织，查询从顶层稀疏图跳到底层稠密图，几步就接近目标。
- **PQ：省存储**。有损压缩，把向量切段，每段只记"代表向量的编号"，存储体积成倍下降。

三种思路可以组合：IVF+PQ 先用分堆缩小计算范围，再用压缩减小存储，是海量数据场景的常见搭配。

## PQ 手算：压缩率这笔账

PQ 的账很好算。一个 128 维向量，每个数 4 字节，占 512 字节。切成 16 段，每段用 256 个"代表向量"之一来替代：每段只需记 1 个字节编号，总共 16 字节，压缩 32 倍。代价是存的是"代表"不是原向量，距离只能估计，会有误差。

```mermaid
flowchart LR
    V[8维原向量] --> S1[前半段 切成2段x4维]
    V --> S2[后半段]
    S1 --> C1[编号 0 离第一个代表最近]
    S2 --> C2[编号 1]
    C1 --> CODE[编码 0,1 共2字节]
    C2 --> CODE
    CODE --> R[解压 代表的拼接 约等于原向量]
```

这个 2 字节的小例子和真实 PQ 流程一致，只是段数更多、代表库更大（256 个代表恰好对应 1 个字节编号）。

## 各库菜单对比：同一原理，不同入口

| 库 | 可选索引 | 谁来选 |
|----|---------|--------|
| FAISS | Flat / IVF / HNSW / PQ 都有 | 你自己选（第 7 章练过） |
| Chroma | 默认 HNSW 系 | 它替你选 |
| Milvus | IVF_FLAT / IVF_SQ8 / IVF_PQ / HNSW 等，最全 | 你选，可按数据换 |
| pgvector | ivfflat、hnsw 两种 | 你选，二选一 |

结论：算法是公用的，差别只在"给不给你选、替不替你调"。Chroma 省心但没得挑；Milvus 自由但需要懂参数。另一个提醒：建索引时还要指定距离度量（L2 / 内积 / 余弦），它和索引算法是两个独立设置，分开决定。

## 小结

- IVF 省计算、HNSW 省路径、PQ 省存储：三种方法通用，不属于任何一家库。
- PQ 切段编码，压缩率 = 原字节数 ÷ 编码字节数，代价是估计误差。
- 各库差异不在算法本身，而在可选索引的自由度与默认策略。
- 索引算法和距离度量是两个独立设置，分别决定。
