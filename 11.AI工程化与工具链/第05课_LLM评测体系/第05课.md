# 第 05 课　LLM 评测体系

前面四课把"运行"管起来了：实验有记录、版本能回滚、指标会告警、链路能追踪。还剩最后一个问题，也是大模型应用最特别的一个问题：回答得好不好，怎么量。延迟有毫秒、成功率有百分比，可"这个回答写得怎么样"是主观的。本课讲怎么给主观的回答建立评分体系。

## 一、凭什么说新版本"更好"

先看两个反面做法：

- "我觉得比上个版本好。"说这话的人是谁，依据是三句聊天记录还是改提示词的作者本人的印象，都不确定。凭感觉做决定，产品方向就没有依据。
- "我测了，都挺好。"测的是自己会问的问题。真实用户会问"外星人什么时候入侵地球"，会把一句话拆成三行问。没测过的场景，上线才暴露。

评测可以用学校考试来理解：选择题机器批卷（客观、快、便宜），作文老师批卷（主观、慢、准）。一套完整的评测体系是两者搭配，不是二选一。

LLM 评测的核心思路相同：固定考题（评测集）→ 自动指标粗筛 → 人工评估把关 → 用分数做决定。

## 二、评测集：先固定考卷

一切的前提是一份**迷你评测集**：几十道有代表性的题 + 每题的参考答案。它的三个要求：

- 覆盖典型场景：简单题、绕弯子的题、知识库里没有的题（考察它会不会编造）都要有；
- **带参考答案**：没有标准答案，机器指标没法算；
- 保持稳定：同一份考卷才能比较不同版本。今天换卷子，分数就不可比。

这和第 01 课"数据要版本化"是一个道理：评测集本身也是要版本管理的资产。

## 三、自动指标：机器批的选择题

对每道题的模型回答，用规则算几个分：

```mermaid
flowchart LR
    A["迷你评测集<br>题+参考答案"] --> B["候选版本<br>v1 / v2"]
    B --> C["自动指标<br>关键词命中/长度/格式"]
    C --> D["人工抽评<br>主观题打分"]
    D --> E["上线决策<br>分数达标才发版"]
```

- **关键词命中**：参考答案里的关键词（如"5 个工作日"）回答里有没有。粗糙但能抓"答非所问"。
- **长度**：太短多半没说清，太长浪费 token 还淹没重点。
- **格式**：该带数字的带没带数字、该分点的有没有分点。

配套的 `llm_eval_demo.py` 就在一套 3 题的迷你评测集上，给两个候选版本逐项打分。纯标准库，直接 `python llm_eval_demo.py`。

## 四、人工评估：老师批的作文

自动指标的天花板很明显："回答流畅吗？语气对吗？有没有隐蔽的事实错误？"这些规则写不出来，只能人来打分：

- 定一个简单量表（比如 1~5 分：1 分给无依据的回答，3 分给能用的回答，5 分给优秀的回答），评分标准写下来，避免各人掌握的尺度不一；
- 抽评而不是全评，控制成本；
- 有条件时可以上"模型当评委"（用一个更强的模型给回答打分），2026 年这已是主流辅助手段；但评委模型自己也会出错，必须配合定期的人工抽评复核，否则评委的偏差没人发现。

关键动作是对照：自动分和人工分摆在一起看。自动分排的序和人工分排的序大致一致，说明指标有效；差得远，就该修指标。本课脚本里做了这个对照，可以看到两版回答"机器怎么想、人怎么想"的逐题对比。

这套"评测集+自动指标+人工对照"的输出，到了第 12 章第 04 课监控 Dashboard 就是"质量趋势"面板的数据源：每次发版前跑一遍评测，分数画成折线，效果衰退直接可见。前面各课留下的衔接在这里汇合。

## 五、上线决策

评测的终点不是分数，是决定：分数达标才发版，不达标打回。呼应第 02 课：candidate → 评测通过 → production，状态机的"评估通过"这一步，靠的就是今天这套体系。到这里，第 11 章五课串成了一个环：实验记录 → 版本注册 → 监控告警 → 链路追踪 → 评测把关。

## 想一想

1. 如果只允许保留一样：评测集、自动指标、人工评估，你留哪个？代价是什么？
2. 自动指标和人工分的排序出现严重分歧，先怀疑哪一方？为什么？
3. （动手）给 llm_eval_demo.py 的评测集加一道"知识库里没有"的题（比如问天气），再想想好回答应该长什么样（提示：承认不知道比编造好）。
4. "模型当评委"省人力，但评委可能偏心哪类回答？怎么发现它偏心？

## 小结

主观回答也要有纪律地打分：先固定评测集（带参考答案、保持版本稳定），再用自动指标（关键词/长度/格式）低成本粗筛，关键的主观维度交给人工量表，"模型当评委"可作辅助但需人工抽评复核，并定期对照两者排序是否一致。分数最终服务决策：达标才上线。第 05 章 mini_rag 的"留现场"习惯，到这里升级成了完整的质量把关。

第 11 章到此收束：实验追踪、版本管理、监控、可观测性、评测，五件事合成一套工程纪律。下一章是第 12 章实战项目，届时带着这套纪律，把前面章节的练习程序做成能上线、能运维、能持续改进的完整系统。
