# 第 03 课　监控与评估

模型上线了，前两课的准备工作完成。系统进入运行阶段：用户在增长、问题在变化、依赖的服务会波动。系统现在是否健康，需要有人持续确认，这就是监控的职责。先看没有它会怎样。

## 一、没有监控，出事全靠用户举报

几个经典场面：

- 服务中断半小时，用户在群里反映之后才知道，然后才去登服务器处理。
- 回答质量悄悄下降没人发现。三个月来用户的问题从"报销流程"漂移到了"AI 写周报"，知识库没有更新，回答质量逐步下滑。没有告警，因为系统没有"坏"，只是"不灵了"。
- 账单突然增大。某个用户写了脚本高频调用，token 消耗涨了 50 倍，月底账单才显现。

监控可以用汽车的仪表盘来理解：不需要实时盯着发动机转速，仪表盘替你盯，油量低了亮黄灯、水温高了亮红灯，亮灯就是告警，其余时候正常开车。

线上监控拆开就三件事：**采集指标 → 和阈值比 → 超了就告警**。

## 二、盯哪些指标

AI 应用和普通 Web 服务有一点不同：除了延迟、成功率这些通用指标，还多了 token 这个"钱"维度。

| 指标 | 说明 | 为什么盯 |
|------|------|----------|
| 延迟 | 一次调用耗时，看 P50/P95 | 用户体感；P95 抓住"最惨的那批人" |
| 成功率 | 请求成功比例 | 最直观的健康线 |
| token 用量 | 每次调用的输入输出 token | 直接关联成本，也是模型负载信号 |

P50/P95 解释一下：把 100 次调用的耗时排队，第 50 名的值就是 P50（一半人比它快），第 95 名是 P95（95% 的人比它快）。平均数会被少数极端值拉偏，P95 更能反映"最差体验"。

AI 还有一个特有的问题：**效果衰退**。模型没改、代码没改，但用户的问题在漂移，知识库过期了，回答就在悄悄变差。运行指标能间接反映迹象，成功率下降、用户重复提问变多，但要确认它，靠的是**评估**：定期拿一组测试题考模型，给效果打分。监控关注运行状态，评估检验回答效果，两个词经常一起出现（所以本课叫"监控与评估"），分工不同。

## 三、最小可用方案：一批调用记录的聚合

不需要一开始就上监控系统。日志文件里的一批调用记录，用纯标准库聚合一下，就是监控的雏形：

```mermaid
flowchart LR
    A["调用记录<br>(延迟/成败/token)"] --> B["按时间窗聚合<br>成功率/P95/token均值"]
    B --> C{"超过阈值?"}
    C -->|是| D["告警: 打印/发通知"]
    C -->|否| E["正常, 继续观察"]
```

配套的 `monitoring_demo.py` 模拟了 200 条调用记录（前 150 条正常，后 50 条故意变差），聚合出两段指标、跑阈值告警。运行后可以看到第二段触发红灯，也就是"衰退被发现了"。纯标准库，直接 `python monitoring_demo.py` 跑。

这页聚合输出不要小看：到了**第 12 章第 04 课做监控 Dashboard** 时，图表背后就是这个东西，只是换成了自动刷新并画成图。

## 四、专业工具与告警的艺术

真实系统里，Prometheus/Grafana 负责采集和画图，告警走邮件、钉钉、Slack。工具会变，但告警设计的三条经验不变：

1. 避免误报泛滥。阈值定得太敏感，天天误报，大家就会把告警静音；最危险的告警是被忽视的告警。
2. 告警要带上下文。"成功率 86% < 95%（最近 10 分钟，/chat 接口）"比"出事了"有用得多。
3. 红灯分两级。"服务中断需立即响应"和"延迟偏高今天看看"必须用不同的响铃方式。

MLflow、LangSmith 这类平台（第 01 课提过）也内置了监控面板，思路一样：把记录集中起来，画出来，超线就告警。

## 想一想

1. 如果只让你盯一个指标，你选成功率还是 P95 延迟？说说你的场景理由。
2. 为什么平均延迟会"骗人"？想一个平均值看起来正常、实际很糟的分布。
3. （动手）把 monitoring_demo.py 里的成功率阈值从 0.95 改成 0.80，重跑看看告警少了什么、可能漏掉什么。
4. 用户问题漂移导致回答变差，运行指标不一定报警。你有什么办法能更早发现这种"没坏但不灵"？

## 小结

线上监控三件事：采集调用记录、聚合关键指标（成功率/延迟分位/token 均值）、超阈值就告警。监控盯运行健康，评估测回答效果，效果衰退要靠两者配合才抓得住。告警要带上下文、要防误报。这页聚合输出就是第 12 章监控 Dashboard 的雏形。

红灯亮了，只能知道"有问题"，还不知道"哪一步有问题"。下一课可观测性，把一次调用拆开逐段看。
