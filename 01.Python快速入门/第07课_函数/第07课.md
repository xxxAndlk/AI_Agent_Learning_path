# 第 07 课　函数

这是第七课。上节课你已经写出了一个像模像样的猜数字游戏：有判断、有循环、能一遍遍问玩家。但你可能也隐隐觉得，那个程序越长越像一团毛线——所有代码从上到下摊成一大片，想改一处，得从头看到尾。

这节课就来做整理。学完之后，你会把第 6 课的游戏亲手拆成几块干净的小块，而且以后写任何程序，都会先想想"这块活儿该交给谁"。

---

## 一、同一段事，别写三遍

先看一个场景。假设你写个程序，逢人就要问好：

```python
print("你好，小明！")
print("祝你今天顺利。")

print("你好，小红！")
print("祝你今天顺利。")

print("你好，老王！")
print("祝你今天顺利。")
```

能跑。可要是哪天你想把"祝你今天顺利"换成"祝你今天开心"，就得改三处；要是有三十个人，就得改三十处。改到第三处的时候人就开始漏改了——这不是你马虎，是代码的写法不对。

生活的经验是：一套固定的流程，人们会把它写成一份菜谱。以后要做这道菜，就照菜谱来一次，而不是每次都重新琢磨一遍。程序里也一样——把这段重复的活儿写成一份菜谱，起个名字，以后喊一声名字，它就照着做。

这份菜谱，就叫**函数**（function）。它是编程里最重要的一件事，没有之一。你这节课学的东西，以后每一行代码都会用到。

---

## 二、def：给一段代码起个名字

写菜谱用 `def` 这个词（define 的缩写，"定义"）。把刚才的问好写成函数：

```python
def greet(name):
    print("你好，" + name + "！")
    print("祝你今天顺利。")
```

先说一件特别容易搞糊涂的事：**运行到这两行时，里面什么都不会发生**。

对，你没看错。`def` 的意思是"我把菜谱写下来，登记在册"，Python 只是记住了"有个函数叫 greet，需要给一个 name"。菜谱写在纸上，没人照着做，桌上是不会有菜的。

要让它真的干活，得**调用**（call）它——喊名字，加上括号：

```python
greet("小明")
greet("小红")
```

这一下屏幕上才会各打出两行问候。想改问候语？只改函数里那一处，所有调用它的地方全部跟着变。这就是函数的第一个好处：**同样的活儿，只写一遍**。

`name` 叫**参数**（parameter），就是括号里那个词。它是函数的"入口"——你调用时往括号里递什么，函数里就拿到什么。参数可以不止一个：

```python
def introduce(name, city):
    print("我叫 " + name + "，来自 " + city + "。")

introduce("小明", "成都")
introduce("小红", "杭州")
```

两个参数用逗号隔开，调用时按顺序对应着递进去。你也可以把函数想成一台售货机：参数是投进去的硬币和按键，它按你的选择出货。

---

## 三、return：把结果递到你手上

到现在为止，我们的函数都只是"干活"——打印几行字，完事。但很多情况下你不想让它打印，你想让它**算出个东西给你**，至于拿去打印还是拿去存起来，由你自己决定。

这就轮到 `return` 出场了。它的意思是"把结果递出去"：

```python
def add(a, b):
    return a + b

result = add(3, 5)
print(result)        # 8
print(add(10, 20))   # 30
```

`add(3, 5)` 这个写法本身，就"等于"算出来的 8——你可以把它存进变量、放进 print、再拿去做别的运算。这和 `print` 是两码事：

- `print` 是售货机对着你广播："您的饮料已出货！"——喊是喊了，你手里什么都没有
- `return` 是售货机真的把饮料递到你手上——你想喝就喝，想转手送人也行

新手最容易在这里栽跟头。记住口诀：**要在函数外面接着用的东西，必须 return，光 print 是拿不回来的。**

还有个小知识：一个函数如果没有写 `return`，或者 `return` 后面空着，它也会递出一个东西——一个叫 `None` 的值，意思就是"什么都没有"。

```python
def say_hi():
    print("嗨")

x = say_hi()
print(x)    # None
```

`say_hi` 只会喊，不会递东西，所以 `x` 拿到的是个空盒子。这不是报错，但如果你以为里面装着值，后面就会莫名其妙地出错。

---

## 四、默认参数：不给也行

有时候某个参数，大多数时候都用同一个值，只有偶尔想换。比如问好，一般问一遍就够，偶尔想热情点问三遍。这种参数可以给个**默认值**：

```python
def greet(name, times=1):
    n = 0
    while n < times:
        print("你好，" + name + "！")
        n = n + 1

greet("小明")       # times 没给，用默认的 1，问一遍
greet("老王", 3)    # 给了 3，问三遍
```

`times=1` 的意思是：调用的人不给这个参数，它就自动取 1。

这里有一条**硬规矩：带默认值的参数必须放在参数列表的最后面**。`def greet(times=1, name)` 这样写，Python 直接报错不让你保存。道理也简单：调用时是按顺序对应传入的，要是默认参数插在中间，Python 就分不清"老王"到底该给谁了。以后定义函数，就按"必给的在前，可不给的在后"来排。

## 五、一次返回好几个结果

`return` 后面可以放好几个值，用逗号隔开，一次打包还回去：

```python
def stats(numbers):
    # min、max、sum 都是 Python 自带的小函数：求最小、最大、求和
    return min(numbers), max(numbers), sum(numbers) / len(numbers)

low, high, avg = stats([80, 92, 75, 61])
print("最低分：", low)
print("最高分：", high)
print("平均分：", avg)
```

`stats` 递回来的其实是三个值打成的包——几个值用逗号排在一起，Python 会把它们捆成一个小包裹（行话叫**元组**，tuple，这词现在知道就行，以后会细讲）。接收的时候写 `low, high, avg = ...`，Python 自动把包裹拆开，按顺序分给三个变量。

这个写法非常常用，尤其是"一个函数算出一堆结果"的场景，比写三个函数各算各的省事多了。

## 六、函数里的变量，外面看不见

接下来是新手最大的一个坑，请坐直了听。

在函数**里面**定义的变量，出了函数就不存在了：

```python
def add_one():
    x = 10        # 这个 x 只活在函数里

x = 1
add_one()
print(x)          # 打出来还是 1，不是 10！
```

为什么会这样？你可以把函数想成一间 KTV 包间，程序的其他部分是大厅。包间里放的东西（函数里定义的变量），客人一走（函数一结束）就全撤了，大厅里根本看不见。反过来，大厅里放的东西（程序顶层定义的变量），包间里倒是看得见——但我们的规矩是：**包间要用大厅的东西，请人从门口递进来（用参数）；要交出结果，走正门递出去（用 return）。**

```python
def add_one(x):       # 要用外面的数？从门口递进来
    return x + 1      # 要交结果？从正门递出去

x = 1
x = add_one(x)
print(x)              # 2
```

这个规矩初看多此一举——都看得见，为什么还要递？因为一旦程序变长，几十个函数都能随手乱改外面的变量，你就再也搞不清"这个数到底是谁改的"。让每个函数只依赖门口递进来的参数、只从正门递出结果，函数才能像积木一样随便拼装、随便搬走。Python 还留了个 `global` 关键字允许你破例，但新手阶段请当它不存在。

---

## 七、先定义，后调用

还有一条规矩要交代：Python 执行脚本是从上往下读的，读到 `greet(...)` 这一行的瞬间，它必须已经认识 greet。所以**调用要写在定义后面**，像这样最常见：

```python
def greet(name):
    print("你好，" + name + "！")

greet("小明")    # 菜谱都写好了，现在才开火
```

要是不小心把调用写在定义前面，Python 会报 `NameError`，说这个名字它不认识——看到这个报错，先检查是不是顺序反了。这也是为什么很多程序把主要流程放进一个叫 `main` 的函数里，在文件**最后一行**才调用它：上面所有"零件"都备齐了，最后才正式开演。

## 八、把大程序拆成小函数

现在把这一切用到真程序上。第 6 课的猜数字游戏，所有代码挤在一起：出题、判断、计数、打印全混着。这节课我们把它重构成 `guess_funcs.py`（重构，refactor——代码还是干那些事，只是重新组织，像房子不换，重新摆家具）：

```python
def make_answer():
    return random.randint(1, 100)

def check_guess(guess, answer):
    ...

def main():
    ...
```

你打开本课目录下的 `guess_funcs.py` 看看，整个文件读起来像一份提纲：`make_answer` 只管出题，`check_guess` 只管判断一次猜测并且把结果 return 回来，`main` 把它们串成主流程。想改提示语？去 `check_guess`。想知道游戏怎么玩？读 `main` 就够了，十行不到。

判断一次猜测的结果是先存在一个变量里、打印完再拿去判断"是不是对了"的——这就用上了前面说的：递到手上的东西，可以接着用。

另外留个伏笔：现在玩家要是输入一个字母，`int()` 会当场翻脸报错。怎么礼貌地接住这种错误？第 8 课见。

## 九、新手最常踩的坑

**函数写了，程序却"什么都没发生"**

多半是光定义没调用。`def` 只是登记菜谱，得在后面写一行 `函数名(参数)` 才会真的执行。

**报 `NameError: name 'xxx' is not defined`**

两种可能：调用写在了定义前面；或者函数里的变量你试图在外面用（包间里的东西，大厅看不见）。

**报 `SyntaxError: non-default argument follows default argument`**

默认参数放在了普通参数前面。调整顺序：必给的在前，带默认值的垫后。

**函数的结果永远是 None**

十有八九是忘了 `return`。光 `print` 是喊给你听，不是递给你。

**在函数里改了一个变量，出来一看没变**

改的其实是包间里的副本。想让外面拿到新值，把新值 `return` 出去，在外面接住。

## 小结

这节课没有新的"魔法"，只有一个思想：**把一段干完一件完整小事的代码，装进有名字的盒子里**。`def` 装盒，参数从门口进，`return` 从正门出，没人调用它就不动。

盒子和盒子互相独立，大程序就是一排盒子加一份提纲。从这节课起，你写程序的方式会不一样了：先想"这件事能拆成哪几件小事"，再一件件装盒。
