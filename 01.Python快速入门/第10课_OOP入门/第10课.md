# 第 10 课　面向对象入门

前面九节课，你已经能用列表、字典和函数写出不少能干活的程序了。这一课要认识一个新东西：**类**（class）。

先把话说在前面：这是面向对象的入门课，只带你建立"类和对象"的基本直觉。你可能听过继承、多态这些听起来很唬人的词，这一课几乎不碰它们——先把最核心的一小块用顺手，比一口气吞下一整套理论有用得多。

---

## 一、先看看现在的写法哪里别扭

回忆一下第 4 课的购物清单：商品数据是一个列表，加东西、删东西、打印这些动作，是散落在代码各处的 `append`、`remove`、`for` 循环。数据是一摊，动作是另一摊。

生意小的时候没关系。可一旦数据多了，你会发现麻烦来了：

- 想写个"宠物"程序？宠物的名字、饱食度用变量存，喂食、玩耍写成函数。函数要碰哪个数据，全靠参数传来传去
- 数据一多、函数一多，谁改了数据，哪些函数要跟着改？全靠你脑子记。总有一次忘了记，程序就出怪毛病

这就像开了家小店，货架上的货和伙计们的做事流程是两本各自为政的账。你把酱油挪了个架子，就得挨个通知三个伙计——总有一次忘通知，客人就要等着。

有没有办法让"货"和"会做的事"长在一起？有。这就是类要干的事。

## 二、类是图纸，对象是照图纸造出来的实物

两个类比，帮你把这两个词焊在脑子里：

**月饼模具和月饼。** 一套模具（类）可以压出无数个月饼（对象）。每个月饼自己带着花纹（数据），也都能被吃掉（动作）。模具本身不能吃——类是规定，对象才是实物。

**建筑图纸和楼。** 一张图纸可以盖出很多栋楼。图纸画的是"每栋楼长什么样、能干什么"，而每一栋盖好的楼都真实立在那里，各自住着各自的人。

所以记住这层关系就够了：**类**是一张图纸，规定了"这类东西记什么数据、会做什么动作"；**对象**是按图纸一个个造出来的实物，每个对象记住自己的数据。

## 三、写出第一个类

光说不练假把式。我们写一只会自我介绍的狗：

```python
class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def bark(self):
        print(f"汪汪，我是{self.name}！")
```

一行行拆开看：

- `class Dog:` 定义了一个类，名字叫 `Dog`。习惯上类名用大写字母开头，比如 `Dog`、`ShoppingCart`，这是全世界的通用约定
- `__init__` 的名字前后各两条下划线（新手最容易少写，后面踩坑表专门说它）。你从来不需要手动调用它——**每次造新对象时它自动运行**，负责把初始数据装进去。可以把 `__init__` 理解成交钥匙时的入住手续：手续一办完，家具就位，拎包入住
- `self` 指的是"我这个对象自己"。`self.name = name` 的意思是：把传进来的名字，记在我自己身上
- `name`、`breed` 这样记在对象身上的数据，叫**属性**——对象记住的东西
- `bark` 这样定义在类里的函数，叫**方法**——对象会做的动作

那怎么"照图纸造对象"呢？类名加括号，像调函数一样：

```python
dog1 = Dog("旺财", "柴犬")
dog2 = Dog("豆豆", "柯基")

dog1.bark()
dog2.bark()
```

`Dog("旺财", "柴犬")` 这一行的真实过程是：Python 先照图纸造出一只空狗，然后自动运行 `__init__`，把 `"旺财"` 和 `"柴犬"` 装进这只狗身上。跑一下，两只狗分别报出自己的名字。

注意调用方法时只写了 `dog1.bark()`，明明 `bark` 定义时要两个参数，这里一个都没传——因为 `self` 不用你管，Python 会自动把对象本身塞进第一个参数。`dog1.bark()` 实际就是"让 dog1 自己喊一声"。

## 四、造出来的对象，各自独立

模具压出的每个月饼都是独立的月饼，对象也一样。试试：

```python
dog1.name = "大旺"
print(dog2.name)   # 还是"豆豆"，一点没受影响
```

改 `dog1` 的属性，动不到 `dog2`。每个对象身上都贴着自己的一套标签，互不串门。将来你写聊天程序，每个用户一个对象，各存各的消息，靠的就是这个特性。

## 五、让 print(对象) 别再输出一串天书

现在试试 `print(dog1)`，你会看到类似这样的东西：

```
<__main__.Dog object at 0x000001A2B3C4D5E6>
```

Python 在说"这是 Dog 类的一个对象，放在内存的某个位置"。对机器有用，对人毫无意义。

想让它说人话，给类加一个 `__str__` 方法，返回你想显示的字符串，`print` 就会自动用它：

```python
class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def __str__(self):
        return f"我是一只{self.breed}，名叫{self.name}"

dog1 = Dog("旺财", "柴犬")
print(dog1)   # 我是一只柴犬，名叫旺财
```

这个小改动平时用不太上，调试的时候特别好使——能直接把对象打印出来看里面装了什么。

## 六、用类改写购物车

```python
        ...

    def show(self):

        ...

    def total(self):

        ...
```

（完整实现看文件，注释里写了每一步为什么。）

用起来是这样的：

```python
cart = ShoppingCart()      # 造一辆车
cart.add("牛奶", 5, 2)     # 加三样
cart.add("面包", 8, 1)
cart.add("苹果", 3, 4)
cart.remove("面包")        # 控糖，删一样
cart.show()                # 打印明细
print("一共", cart.total(), "元")
```

对比一下第 4 课的写法，体会这节课最重要的一句话：**数据和操作它的动作，现在绑在一起了**。清单数据不再裸奔在某个变量里等人来改，而是住进了车自己身上；`cart.add(...)` 一喊，车自己就把货装好了。你甚至可以再造一辆 `another = ShoppingCart()`，两辆车各装各的货，互不干扰——第 4 课那一个全局列表可做不到。

## 七、以后你会碰到：继承

类还有一个大本事叫**继承**：一个类可以把另一个类的能力整个拿过来用，再补上自己的特色。比如"动物"类会吃东西，"狗"类继承它，天生就会吃，再添一个"汪汪叫"。

现在知道有这回事就行，本课不展开——`self` 和 `__init__` 用顺了，以后再学事半功倍。

## 八、新手最常踩的坑

**报错 `TypeError: bark() takes 0 positional arguments but 1 was given`**

类里定义方法时忘了写 `self`。Python 调用时会偷偷把对象塞进第一个参数，你不给它留位置，它就把对象硬塞给你看。定义时补上 `self` 就好。

**报错 `NameError: name 'xxx' is not defined`（方法里面）**

方法里用了光溜溜的 `name`。它记在对象身上，要写 `self.name` 才能取到。

**报错 `AttributeError: 'Dog' object has no attribute 'name'`**

多半是 `__init__` 拼错了——写成 `_init_`（各一条下划线）或 `__int__`，Python 不报错也不拦你，只是造对象时啥都没装进去。记住：前后各两条下划线。

**`remove` 一个购物车里没有的东西，程序崩了**

第 4 课说过直接删不存在的值会报错。`oop_cart.py` 里的做法是先找一圈，找到了才删，找不到就客客气气说一句"没有"，程序继续跑。

## 小结

这节课你只需要带走三件事：类是图纸、对象是照图纸造的实物；`__init__` 在造对象时自动运行，`self` 是"我自己"；属性是对象记住的数据，方法是对象会做的动作。

第 4 课的购物清单到这一课变成了类版购物车——你能感觉到，数据和动作绑在一起之后，程序反而更有条理了。下一课我们讲地道的 Python 写法：推导式、生成器，让同样的逻辑写出来更短更漂亮。
