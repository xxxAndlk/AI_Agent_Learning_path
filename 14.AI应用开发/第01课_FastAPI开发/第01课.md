# 第 01 课　FastAPI 开发

第 12 章的实战项目是命令行程序，只能在本机运行。要让网页、小程序等客户端用上你的模型调用，需要把它变成网络服务。这一课写的就是第 13 章四层结构里的接口层：接收请求、返回结果。

## 先建立一条主线：前端展示，后端干活

以网页版情绪分析为例。用户在页面上输入一句话、点"分析"，结果显示在页面上。分工是：页面（前端）负责展示，服务器上的 Python 程序（后端）负责调用模型，两者通过接口通信。

可以类比一家餐厅：你在大堂看菜单点菜，不必进厨房；前台把单子递给厨房，厨房做好后从同一个窗口端出来。接口就是那个窗口：前后端约定好，窗口收什么单子、递出什么菜。

- **接口（API）**：前后端的约定，规定访问地址和可办理的业务
- **HTTP 请求**：客户端发给服务器的消息。GET/POST 是请求方式，请求体是携带的数据，响应是服务器的返回
- **JSON**：前后端通用的数据格式，字段名和类型有明确约定，任何语言都能解析

```mermaid
flowchart LR
    A["浏览器（前端页面）"] -->|"HTTP 请求"| B["接口 /api/sentiment"]
    B --> C["后端函数：调模型/算逻辑"]
    C -->|"JSON 结果"| B
    B -->|"HTTP 响应"| A
```

这条主线贯穿本章：前端负责展示，后端负责执行逻辑，接口负责在两者之间传递数据。

## 用标准库写一个真接口（零依赖，可直接运行）

不用安装任何东西。Python 标准库里的 `http.server` 模块就能启动一个真实的 HTTP 服务：

```
cd 14.AI应用开发/第01课_FastAPI开发
python fastapi_demo.py
```

浏览器打开 `http://127.0.0.1:8765`，会看到一个小页面：输入一句话点"分析"，情绪结果就返回了。这是一个真实的前后端配合：页面是前端，`/api/sentiment` 是后端接口。Windows 控制台中文显示异常时，改用 `PYTHONIOENCODING=utf-8 python fastapi_demo.py` 启动。

打开 `fastapi_demo.py` 看三个关键位置：

1. `do_GET` 里 `url.path == "/"` 时返回 `PAGE`：浏览器访问首页，服务器递回一整段 HTML
2. `/api/sentiment` 时执行 `fake_model(q[0])` 再 `_json(...)`：收请求、执行函数、返回结果，这就是接口的全部工作
3. `fake_model()` 目前用关键词打分，模拟模型的返回；换成真实大模型只需要改这个函数（后面讲）

另外，`python fastapi_demo.py --selftest` 会自动启动服务、发送几条请求验证接口、再关闭服务。本章每个网页程序都带这个自检。

## FastAPI：把同一件事写得更短更稳

标准库版帮你看清接口的本质，真实项目一般用框架。安装（缺库时 `fastapi_demo.py` 会打印中文提示并跳过真实段，零依赖部分不受影响）：

```
pip install fastapi uvicorn
```

同一个情绪接口，FastAPI 写法只有几行（`fastapi_demo.py` 文件末尾有完整对照版）：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class SentimentIn(BaseModel):
    text: str          # 约定请求体必须带 text 字段

@app.post("/api/sentiment")
def sentiment(item: SentimentIn):
    return fake_model(item.text)
```

框架省掉的不只是代码：

- `@app.post("/api/sentiment")` 一行完成路由登记，URL 分发不再手写 if-else
- `BaseModel` 自动校验参数：缺少 text 字段、类型不对时，FastAPI 直接返回错误说明，不需要手写检查
- 启动用 2026 年官方 CLI：`fastapi dev fastapi_demo.py`，改代码自动重启；旧写法 `uvicorn fastapi_demo:app --reload` 也仍然可用
- 启动后访问 `/docs`，是自动生成的交互式接口文档，在页面上就能直接发请求测试

## 换成真实模型：只改函数内部

接入大模型时，接口、校验、文档都不用动，只修改 `fake_model` 的内部（示意，需 API Key，本课未实跑）：

```python
import os
from openai import OpenAI   # pip install openai

def fake_model(text: str) -> dict:
    client = OpenAI()       # 默认从环境变量 OPENAI_API_KEY 读密钥
    resp = client.responses.create(
        model="gpt-4o-mini",   # 示例名，请按官网当前模型列表替换
        input=f"判断这条评论的情绪，只回答：积极/消极/中性。评论：{text}")
    return {"label": resp.output_text.strip(), "score": None}
```

两条纪律：密钥只从环境变量读取，不写进代码；新代码用 Responses API（`client.responses.create`），旧的 `chat.completions` 写法在网上仍大量可见，会读即可。

1. 浏览器地址栏回车通常是 GET 请求。为什么"分析情绪"要用 POST？把待分析的长文本挂在网址上传，可能出什么问题？

## 小结

前端负责展示，后端负责执行逻辑，接口是两者之间的约定。用标准库 http.server 就能写出一个真实接口，本质是"收请求、执行函数、回响应"三步。FastAPI 用更少的代码完成同样的事，并提供自动校验与自动文档，是当前 Python 后端接口的主流选择。接入大模型只需要替换接口函数的内部实现，其余结构不变。
