# 第 01 课　FastAPI 开发

你写的 Python 脚本有个天然局限：只能在你自己的电脑上、由你自己跑。模型再聪明，躺在 .py 文件里别人也用不上。这一课解决第一跳——把一个函数变成网络上任何人都能访问的服务。

## 先建立一条主线：前端展示，后端干活

想象一家餐厅：你坐在大堂（前端页面）看菜单点菜，不需要进厨房；服务窗口接过菜单递给厨房（后端），做好后从窗口把菜端出来。"接口"就是那个窗口——前后端约好：窗口收什么单子、递出什么菜。

- **接口（API）**：前后端约定的"窗口"，规定了访问地址和能办理的业务
- **HTTP 请求**：寄快递——网址是收件地址，GET/POST 是寄件方式，请求体是包裹，响应是回执
- **JSON**：像标准化的快递面单，前后端都认这种格式，不会因为字迹潦草扯皮

```mermaid
flowchart LR
    A["浏览器（前端页面）"] -->|"HTTP 请求"| B["接口 /api/sentiment"]
    B --> C["后端函数：调模型/算逻辑"]
    C -->|"JSON 结果"| B
    B -->|"HTTP 响应"| A
```

记住这条主线，后面所有网页应用都是它的变体：**前端负责展示，后端负责干活，接口负责传话**。

## 徒手搓一个真接口（零依赖，今天就能跑）

不用装任何东西。Python 标准库里有个叫 `http.server` 的模块，能真的把服务起起来：

```
cd 14.AI应用开发/第01课_FastAPI开发
python fastapi_demo.py
```

然后浏览器打开 `http://127.0.0.1:8765`——你会看到一个小页面：输入一句话点"分析"，情绪结果就出来了。这不是截图、不是模拟，是一个真的前后端配合：页面是前端，`/api/sentiment` 是后端接口。

打开 `fastapi_demo.py` 看三个关键位置：

1. `do_GET` 里 `url.path == "/"` 时返回 `PAGE`——浏览器访问首页，我们递给它一整段 HTML
2. `/api/sentiment` 时执行 `fake_model(q[0])` 再 `_json(...)`——这就是"窗口收单、厨房做菜、递出结果"
3. `fake_model()` 现在用关键词打分，假装是个模型；换成真大模型只改这个函数（后面讲）

另外 `python fastapi_demo.py --selftest` 会自动起服务、发几条请求验证接口、再关掉——这就是"真起真关"，本章每个网页程序都带这个自检。

## FastAPI：把同一件事写得又短又稳

徒手搓帮你看清本质，真实项目用框架。装它（缺库时 `fastapi_demo.py` 会打印中文提示并自动跳过真实段，不影响零依赖部分）：

```
pip install fastapi uvicorn
```

同一个情绪接口，FastAPI 写法只有几行（`fastapi_demo.py` 文件末尾就有完整对照版）：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class SentimentIn(BaseModel):
    text: str          # 约定请求体必须带 text 字段

@app.post("/api/sentiment")
def sentiment(item: SentimentIn):
    return fake_model(item.text)
```

省掉的不只是代码：

- `@app.post("/api/sentiment")` 一行就完成"窗口登记"，URL 分发不用手写 if-else
- `BaseModel` 自动验收参数：缺了 text、类型不对，FastAPI 自己回错误说明，你不用手写检查
- 用 `uvicorn fastapi_demo:app --reload` 启动（新版 FastAPI 还提供了更省事的 `fastapi dev fastapi_demo.py`）；改代码自动重启
- 启动后访问 `/docs`——自动生成的交互式接口文档，页面上直接点"Try it out"就能试调用，相当于餐厅把菜单挂墙上还能现场试菜

## 换成真模型：只换函数身体

接大模型时，接口、校验、文档全都原封不动，只改 `fake_model` 的内部（示意，需 API Key，本课未实跑）：

```python
import os
from openai import OpenAI   # pip install openai

def fake_model(text: str) -> dict:
    client = OpenAI()       # 默认从环境变量 OPENAI_API_KEY 读密钥
    resp = client.responses.create(
        model="gpt-4o-mini",   # 示例名，请按官网当前模型列表替换
        input=f"判断这条评论的情绪，只回答：积极/消极/中性。评论：{text}")
    return {"label": resp.output_text.strip(), "score": None}
```

两个纪律：密钥只从环境变量读，绝不写进代码；新代码用 Responses API（`client.responses.create`），老的 `chat.completions` 写法网上仍大量可见，会认即可。

## 想一想

1. 浏览器地址栏回车通常是 GET 请求。为什么"分析情绪"要用 POST？把待分析的长文本挂在网址上传，可能出什么问题？
2. 我们顺手做了个 `GET /api/health` 返回 `{"status": "ok"}`。你觉得谁会天天来访问这个接口？它有什么用？
3. 餐厅只有一个窗口，同时来一百个人点单会怎样？结合"调模型要等好几秒"，想想服务端有什么应对思路。
4. 轻动手：给 `fastapi_demo.py` 加一个 `GET /api/echo?msg=你好` 接口，原样返回 `{"echo": msg}`。重启服务，在浏览器里试通它。

## 小结

前端负责展示，后端负责干活，接口是两者约定的窗口。用标准库 http.server 就能徒手搓出真接口，本质是"收请求、执行函数、回响应"三步。FastAPI 用几行代码加上自动校验和自动文档完成同样的事，是当下 Python 后端接口的主流选择。接大模型只是换掉接口函数里的几行，其余结构不变。

下一课把今天这个"一问一答"的接口，升级成一个能连续对话、回答逐字蹦出来的聊天网页——像模像样的 AI 产品就从那里开始。
