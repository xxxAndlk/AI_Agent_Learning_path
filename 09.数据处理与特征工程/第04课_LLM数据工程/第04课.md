# 第 04 课　LLM 数据工程

前三课讲的是手工时代的数据手艺：清洗、挑特征、做增强。手工造数据有个上限：一天几百条，而微调一个模型动辄需要几千上万条。这节课把产能问题交给大模型本身：让 LLM 批量造数据、改数据、查数据。这也是 2026 年做 AI 的日常工作方式。

## 一、流水线式生成，不是一句话生成

新手常见的做法是打开聊天窗口说"帮我生成 1000 条客服数据"，结果是一千条内容高度雷同的数据。可行的做法是把 LLM 嵌进一条**流水线**：人定好模板和规则，LLM 负责批量生成，程序负责质检，人最后抽检。一句话概括分工：

> LLM 承担批量生成，人定规则、做抽检。

```mermaid
flowchart LR
    A[人:设计模板<br/>写好 few-shot 例子] --> B[LLM:批量生成/改写]
    B --> C[程序:规则质检<br/>长度/缺字段/格式]
    C -->|不合格| B
    C -->|合格| D[人:抽样复核]
    D --> E[入库:指令数据 / RAG知识库]
```

三个角色缺一不可：没有模板，生成内容会偏离需求；没有程序质检，错误会批量复制；没有人工抽检，"看起来对、实际错"的数据会留在库里影响模型。

## 二、造什么：指令数据和 RAG 数据

大模型时代要造的数据主要有两大类。

**第一类：指令数据（Instruction Data）**，微调用的"题库"。每条长这样：`{"instruction": "把这句客服话术改得更友好", "input": "已经说三遍了，自己看说明书", "output": "好的，我一步步带您看～"}`，指令说明要干什么、输入是什么、期望输出长什么样。你在第 2 章第 09 课（模型微调）见过它的用途：微调就是拿这批"题目+标准答案"去训练模型。造法通常是"人写 10 条种子例子 → LLM 照着批量扩写到几千条 → 质检去重 → 人抽检"。种子例子的质量决定扩写质量，这就是模板和 few-shot 由人写的原因。

**第二类：RAG 知识数据**，给知识库准备检索材料。流程你已经见过：文档加载 → 切块（chunking）→ 向量化入库，这正是第 5 章 RAG 那一课搭过的 Pipeline。LLM 在这里能做三件事：把扫描版文档里的乱码整理成干净文本；给每一块生成摘要和标题（检索时更准）；从文档里反向生成练习题（既当指令数据，又当检索测试题）。

一个常被忽略的常识：这两类数据的质检标准不同。指令数据怕"答案错"（要人抽检语义）；RAG 数据怕"切块烂"（要检查块长、断句、字段完整），后者程序能自动查得多，这正好接上一课"质检交给规则"的思路。

## 三、动手：离线版流水线

配套 `llm_data_demo.py` 用纯标准库模拟了一条最小流水线：**批量模板生成**（种子模板 × 多个槽位值，程序化造出指令数据）+ **规则质检**（长度超没超、关键字段缺没缺、输出内容是不是空洞），不合格的当场拦下并打印原因。这段零依赖、本机可真跑，把其中的"模板生成器"换成 LLM 调用，就是真实流水线的形状。

真实调用 LLM 的批量段在文件后半部分（需 `pip install openai` 和 API Key，本讲义未实跑；缺库或缺 Key 时程序打印中文提示并优雅跳过）：结构一模一样，只是"生成"这一步从模板换成了 `client.responses.create(...)`。Key 一律从环境变量读，代码里没有硬编码密钥。三条经验写在注释里：控制并发，避免超出限额；温度调低一点，输出更稳定；每条都先过程序质检再落盘，不盲目信任 LLM 的输出。

## 四、数据闭环：本章的收束点

四课连起来是一条完整的流程：

- 第 01 课清洗，保证原料干净；
- 第 02 课挑特征，保证模型用得对症；
- 第 03 课增强，不够时合理加量；
- 本课用 LLM 放大产能，批量造出指令数据和 RAG 数据。

造好的数据有两个去处：指令数据回流到第 2 章的模型微调，训练模型的行为；RAG 知识库回流到第 5 章的 RAG 系统，支撑检索问答。这与第 01 课"垃圾进，垃圾出"是同一件事的两面：数据质量决定这两个系统的上限。

## 想一想

1. 用 LLM 批量生成指令数据时，为什么要先人工写 10 条种子例子，而不是直接说"随机生成 1000 条"？
2. 程序规则质检能查出"输出太短""缺字段"，但查不出"输出事实性错误"。这道防线该怎么补？
3. 同一批文档，既想当 RAG 知识库又想出指令数据，哪些工序可以共用，哪些必须分开做？
4. 轻动手：往 `llm_data_demo.py` 的质检规则里加一条"output 必须以句号或感叹号结尾"，再跑一遍，看哪几条会被拦下。

## 小结

- LLM 造数据的分工：人定模板和规则，LLM 批量生成，程序质检，人抽检。
- 指令数据（instruction/input/output）用于微调，RAG 数据用于知识库；造法不同，质检标准也不同。
- 不盲目信任 LLM 输出：程序规则先拦一道，人工抽检收最后一道关。
- 造好的数据回流到第 2 章微调与第 5 章 RAG，完成数据闭环。
- 数据这条线到此收束，下一章进入第 10 章：模型部署与推理优化，把训练好的模型真正跑起来并做优化。
