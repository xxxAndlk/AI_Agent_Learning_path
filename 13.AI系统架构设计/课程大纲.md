# AI 系统架构设计 · 课程大纲

前面你学会了一个个技术点，也做了小项目。但当系统变大、用户变多、要求变高，问题就不再是"这个功能怎么实现"，而是"整个系统该怎么搭"：要分几层？数据怎么流？哪些地方会成为瓶颈？怎么保证可靠、安全、可扩展？这就是架构设计要回答的。

这一章我们站在更高处，把前面学过的 LLM 应用、RAG、Agent、MCP 工具、AI SaaS 分别画成完整的架构图，讲清每个模块的职责、它们怎么协作、真实落地时有哪些常见坑和取舍。这一章不写大量代码，重在培养"系统思维"，也是从执行者走向能独立负责项目的关键一步。

## 学习之前

- 建议已学完第 03～12 章，对各类 AI 应用"由什么零件组成"有直观认识
- 本章会出现不少架构图，建议边看边自己画一遍，理解模块和数据流比记住名词重要
- 架构没有唯一标准答案，重点是学会"面对需求和约束，如何权衡与取舍"

## 课次安排

| 课次 | 主题 | 你会搞懂的事 |
|------|------|--------------|
| 第 01 课 | LLM 应用架构 | 一个能上线的大模型应用该分几层；模型、提示、编排、接口怎么组织（接口层的代码实现见第 14 章） |
| 第 02 课 | RAG 系统架构 | 从数据接入到检索生成的完整链路；离线建库与在线问答怎么配合 |
| 第 03 课 | Agent 系统架构 | Agent 的运行时、状态、工具、记忆怎么搭；复杂 Agent 如何编排 |
| 第 04 课 | MCP 工具架构 | 工具的客户端、服务端、资源怎么组织；如何统一管理大量工具 |
| 第 05 课 | AI SaaS 架构 | 多租户、配额计费、模型网关、高可用怎么设计；从产品到系统 |

## 怎么学

1. 每课先看全景架构图，再逐个模块理解"它负责什么、和谁交互"
2. 始终带着"约束与取舍"的眼光：成本、延迟、可靠性、安全性，架构是平衡的艺术
3. 把本章架构图和第 12 章实战项目对照着看，能体会"小 demo"到"生产系统"的差距
4. 试着为一个你熟悉的场景自己画一版架构，再和课程对比，进步最快
